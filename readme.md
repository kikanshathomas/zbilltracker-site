# zbilltracker-site

The marketing website for Zombie Bill Tracker, served at <https://zbilltracker.com>.

This repository is the only source of the site. It is published with GitHub Pages from
the `main` branch (custom domain in `CNAME`), so **whatever is on `main` is live**:
merging a pull request here is a publish and is reviewed like any public content.
There is no build step; the files are served exactly as committed.

## Page set

The site follows the internal product standard for marketing sites, which fixes the
page set to exactly these files:

| Path | Purpose |
|---|---|
| `index.html` | Home page (features, benefits, FAQ, download call to action) |
| `download.html` | Download page (Google Play badge and QR code) |
| `privacy.html` | Privacy policy, with its effective date |
| `404.html` | Not-found page (no nav, no footer) |
| `CNAME`, `.nojekyll` | Custom domain; serve files as-is without Jekyll |
| `robots.txt`, `sitemap.xml` | Crawler rules and sitemap (update `lastmod` when a page changes) |
| `favicon.ico`, `favicon-32x32.png`, `apple-touch-icon.png` | Browser and home-screen icons |
| `assets/img/` | `app-icon.png`, `og.png` (1024x500 share banner, also the Play feature graphic), `google-play-badge.png`, screenshots (460x818 PNG plus 2x WebP) |
| `assets/css/fonts.css`, `assets/fonts/` | Self-hosted Outfit font |
| `assets/js/qrcode.min.js` | QR code on the download page |

No other pages are added. `readme.md` and `changelog.md` are repository documents;
they are not linked from the site.

The site art (`app-icon.png`, `og.png`, the favicons and `apple-touch-icon.png`) is
generated by a script in the private development repository, which writes into a
sibling checkout of this repository. Change the generator rather than editing that art
by hand.

## How changes ship

1. Create a feature branch named `<type>/<topic>` (for example `fix/privacy-wording`).
2. Make the change and add an entry under `Unreleased` in `changelog.md`.
3. Push the branch and open a pull request against `main`. Nobody pushes to `main`
   directly.
4. The pull request gets a DevOps security check and QA review. The owner approves it
   and the CEO merges it.
5. GitHub Pages deploys `main` automatically, usually within a few minutes.

## Verifying the live site

A merged pull request only shows that the repository is correct. Check what visitors are
actually served, and repeat until the change appears (Pages and its CDN can take several
minutes; the query string avoids a cached copy):

```sh
# Status and cache headers
curl -sI "https://zbilltracker.com/privacy.html?v=$(date +%s)"

# A string the change introduced, e.g. the privacy policy effective date
curl -s "https://zbilltracker.com/privacy.html?v=$(date +%s)" | grep -o 'Effective date: <time[^>]*>'

# Byte-compare a page with the committed file
curl -s "https://zbilltracker.com/index.html?v=$(date +%s)" | cmp - index.html && echo identical
```

Only describe a change as live once the served pages match the repository.
